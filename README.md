# Лабораторна робота №2. Бекенд без БД

**Варіант 7: Сервіс реєстрації на факультатив/подію**

### Як запустити бекенд

1. Відкрийте термінал і перейдіть у папку бекенда (або проекту):
```bash
cd lr2-api
```

2. Встановіть залежності:
```bash
npm install
```

3. Запустіть сервер в режимі розробки:
```bash
npm run dev
```

Сервер запуститься за адресою: http://localhost:3000

### Реалізовані сутності

* **Користувачі (Users)** (поля: id, name, email)
* **Події (Events)** (поля: id, title, date, location, capacity, description)

### Приклади запитів (cURL)

1. Створити нову подію (Успіх - 201 Created):
```bash
curl -i -X POST http://localhost:3000/api/events -H "Content-Type: application/json" -d "{\"title\":\"Екзамен з програмування\",\"date\":\"2026-06-25\",\"location\":\"Ауд. 315\",\"capacity\":50,\"description\":\"Обов'язкова присутність\"}"
```

2. Помилка перевірки (400 Bad Request - пустий заголовок або коротка назва):
```bash
curl -i -X POST http://localhost:3000/api/events -H "Content-Type: application/json" -d "{\"title\":\"\",\"date\":\"2026-06-25\",\"location\":\"Ауд. 315\",\"capacity\":50}"
```

3. Отримати список усіх подій (200 OK):
```bash
curl -i http://localhost:3000/api/events
```

4. Отримати список усіх користувачів (200 OK):
```bash
curl -i http://localhost:3000/api/users
```

# Лабораторна робота №3 — REST API з SQLite

**Варіант: Сервіс реєстрації на факультатив/подію** Бекенд-система для автоматизації запису студентів на додаткові заняття та заходи, що дозволяє керувати списком подій, базою користувачів та відстежувати реєстрації в режимі реального часу.

## Як запустити проєкт

1. **Встановіть залежності:**
   ```bash
   npm install
   ```

2. **Запустіть сервер у режимі розробки:**
   ```bash
   npm run dev
   ```

**Порт за замовчуванням:** Сервер запуститься на [http://localhost:3000](http://localhost:3000)

## База даних та ініціалізація

* **СУБД:** SQLite.
* **Файл бази:** Автоматично створюється за шляхом `data/app.db`.
* **Схема:** Таблиці створюються автоматично при першому старті за допомогою SQL-команд `.
* **Seed (Тестові дані):** Реалізовано механізм автоматичного наповнення бази. Якщо таблиця користувачів порожня, система додає тестові записи для користувачів, подій та реєстрацій для демонстрації зв'язків.

## Схема БД (Структура)

В системі реалізовано 3 взаємопов'язані сутності:

1.  **Users (Користувачі):** `id`, `name`, `email` (unique).
2.  **Events (Події):** `id`, `title`, `date`, `location`, `capacity`, `description`.
3.  **Registrations (Реєстрації):** `id`, `eventId`, `userId`, `registeredAt`.
    * **Зв'язок:** `FOREIGN KEY (eventId) REFERENCES Events(id) ON DELETE CASCADE`.
    * **Зв'язок:** `FOREIGN KEY (userId) REFERENCES Users(id) ON DELETE CASCADE`.
    * **Обмеження:** `UNIQUE(eventId, userId)` — один користувач не може зареєструватися на ту саму подію двічі.

## Приклади запитів (cURL)

### 1. Отримати всі реєстрації (3-тя сутність з JOIN)
Демонстрація отримання даних із пов'язаних таблиць (ім'я користувача + назва події):
```bash
curl -i http://localhost:3000/api/registrations
```

### 2. Складний запит (WHERE + ORDER BY + LIMIT)
Приклад отримання подій у конкретній локації із сортуванням за датою:
```bash
curl -i "http://localhost:3000/api/events?location=Ауд.315&sort=date&order=desc&limit=5"
```

### 3. Створити нову реєстрацію (Успіх - 201 Created)
```bash
curl -i -X POST http://localhost:3000/api/registrations -H "Content-Type: application/json" -d "{\"eventId\": 1, \"userId\": 1}"
```

### 4. Отримати користувача за ID
```bash
curl -i http://localhost:3000/api/users/1
```

## Технічні особливості

* **Повний CRUD:** Реалізовано асинхронні методи `POST`, `GET` (list/id), `PUT` та `DELETE` для всіх сутностей.
* **Централізована обробка помилок:** Middleware перетворює SQL-помилки у зрозумілі відповіді: `409 Conflict` для дублікатів та `400 Bad Request` для неіснуючих ID.
* **Логування:** Сервер фіксує кожен запит та ключові події БД (відкриття файлу, ініціалізація схеми).
* **Безпека:** Додано файл `.gitignore` для запобігання завантаженню локальної бази даних у репозиторій.
